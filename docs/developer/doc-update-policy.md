# 开发者文档：文档更新规范（强制）

## 目标

任何功能改动完成后，文档必须同步，不允许“代码先走、文档滞后”。

## 每次功能完成后的必做项

1. 更新调用链路文档  
   - 文件：`/docs/developer/call-chains.md`  
   - 要写清楚：入口事件、核心模块、状态变更、UI 落点。
2. 更新使用文档  
   - 文件：`/docs/usage/*`  
   - 要写清楚：怎么用、有什么变化、如何验证。
3. 更新开发者文档  
   - 文件：`/docs/developer/*`  
   - 要写清楚：代码位置、改造边界、回归风险。
4. 更新代办日志  
   - 文件：`/ui-modularization-todo.md`  
   - 要写清楚：改动范围、验证结果、遗留问题。

## 合并前检查清单

- [ ] 调用链路已更新
- [ ] 使用文档已更新
- [ ] 开发者文档已更新
- [ ] 代办日志已更新
- [ ] docs 构建通过（`pnpm --dir docs docs:build`）
